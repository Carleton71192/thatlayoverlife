## The diff, read line by line (against A3, the repair round in detail)
1. Reload nudge, at the top of the story layer: on a reload or back_forward navigation, with scroll restoration not manual and the page not yet loaded, a load listener scrolls to y-1 and back to y in one task when scrollY is at least 1. It runs only on /stories/ paths. Questions I tried: does it fight a reader who scrolls while the page loads (wheel during load), does it move a reload at the very top (y 1) or at the bottom, does it change a reload that comes back to the Receipts link target (#receipts), and does it hold on slow 4G. Results in item 3 of "What held up".
2. document.addEventListener wrapper (wal): installed when the early run starts, removed when the template script has been parsed or at DOMContentLoaded, and only if it is still the current function. Every call goes to the function that was current at install time (dal) with the same arguments. Side effects found: a script that patches EventTarget.prototype.addEventListener after the hero and before the template script is bypassed for calls on document in that window (note 4); a script that wraps document.addEventListener itself in that window keeps its wrapper and the template detection still works (thirdWrap cases).
3. keep(): at the end of parsing, if no element next to the stand-in holds an img, the stand-in stays with visibility hidden; its observer stays connected, so flags that come later still replace it in the same step. A stand-in that left with the old crumb (the template made a link of it) is let go as before. Consequence: a finished crumb can keep an empty box (note 1).
4. The template detection reads document.currentScript in both the wrapper and the error listener, so a throw before the DOMContentLoaded listener releases at once and a throw after it waits; both measured (failTmpl, failTmplSyntax, failTmplLate).

## Notes, worst first (none of them blocks the test site by this check's rule)
1. **The empty flag box stays in the finished crumb when no flag comes.** This is the price of the ADV1 fix and it is visible. On Balkans at 360 with the flag script failing, the crumb keeps a hidden box 137 px wide in front of "BALKANS", so the text starts 149 px in and the breadcrumb stays two rows (73 px) where www has one (44 px). It is not only a failure case: the static country table holds Chromium's names, and other engines name a few places differently. Node 22 (ICU 77, CLDR 47) differs from region-names-v1.json for 4 of 280 regions: HK "Hong Kong SAR China", MO "Macao SAR China", PS "Palestinian Territories", FK "Falkland Islands". Firefox and Safari use stock CLDR names, so a "Hong Kong" or "Macao" crumb there gets the stand-in, no real flag, and now a permanent blank where www shows nothing (emulated with an Intl stand-in: zz-hongkong-oldintl and zz-turkiye-oldintl end with the hidden box on 2 of 2 loads; CLS is not worse, 0.015 to 0.021). No saved story crumb names one of these places today. A cheap guard would be to give no stand-in for the few codes whose names differ between engines (a small shift, as on www, instead of a lasting gap).
2. **Template script missing from the page: Southern Africa 390 scores 0.157 on A4R (www 0.058, A2 0.074, A3 0.165).** That is 0.083 worse than both, under the 0.1 line.
