Review notes

  1. Badge row sits under the name on the public profile (Contributors Template). Only earned badges render; there are no empty or greyed-out slots on a public page. Each badge is a 44 px tall link to a short "What the badges mean" note.
  2. Stats: countries from the map record by the counting rule, out of 249; stories counted from the published Stories list on the page. The hand-typed Country count and Published count fields are no longer shown.
  3. First Story: built natively. A hidden Stories list on the profile (contributor = current profile, published, oldest first, limit 1) holds the badge itself, so it only renders when a story exists, and its date is that story’s date. No script.
  4. 10 Countries: the count lives in each member’s map record, and only your record has a public copy today (owner-record.json). So the badge shows on your profile now, on a member’s own view of their profile, and on everyone else’s public profile once the public map store from S03 exists. It reads the same count the existing profile script (tll-pf3-profile-js-v1) already computes; that script gets a few lines, no new script.
  5. Featured: two new Contributors fields (the collection has 54 of 60 custom fields today, so there is room). The existing "Is featured" switch keeps its job (the one home slot), and the existing "Badge" option (Founder, Editor) stays a role label, not an earned badge.
  6. Directory and hub cards show the same badges small, after the "knows" line. Order on /travelers stays shuffled per visit; badges never sort.
  7. Progress is private. The research says badges pull effort near a threshold, so the "7 of 10" nudge appears only on the member’s own /account, never on a public page. This is a small addition to the account 3.0 Overview tab, inside the members block, without touching any data-ms element.
