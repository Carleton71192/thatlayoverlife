## Review item 1: every section fades in late (opacity near 0 until it reaches the viewport); cut the reveal to 200 to 300 ms and start from 0.6

Findings:

- Mechanism: the only active reveal on the home page is the registered Webflow script tllReveal 1.1.0, a site-wide footer script (src/pages/profile/v3/orig/site-scripts.json lines 35-40: id tllreveal, version 1.1.0, location footer). It is not inline: it is a hosted file, https://cdn.prod.website-files.com/69d6145cf421c777840c1e25%2F689e5ba67671442434f3ca35%2F6ab3dccf06008eac8df3668a%2Ftllreveal-1.1.0.js (script tag at saved _home.html line 1777 and live home line 1777; all 14 saved pages in scratchpad/p0 load it). Downloaded copy: /tmp/claude-0/-home-user-thatlayoverlife/16a08c1e-77ab-50a3-8cf3-b364d5e24f1b/scratchpad/p0/agents/p0-item1/dl/tllreveal-1.1.0.js (1,797 bytes).
- Current values, quoted from tllreveal-1.1.0.js: injected style '.tll-rv{opacity:.01;transform:translateY(14px);transition:opacity .7s ease,transform .7s cubic-bezier(.2,.7,.2,1)}.tll-rv.tll-rv-in{opacity:1;transform:none}'. Observer: new IntersectionObserver(..., {rootMargin:'0px 0px -40px 0px'}) with the default threshold 0, so an element has to be 40 px inside the bottom edge before it starts. Stagger: dl=Math.min(i++,4)*80, i.e. 0 to 320 ms transitionDelay per batch, then classes removed at 800+dl ms. So: starting opacity 0.01, translate 14 px, duration 700 ms, delay 0 to 320 ms, worst case about 1,020 ms from entering to fully visible, and nothing starts until the element is already 40 px on screen.
- Which elements: tllReveal marks the direct children (or one-level-down children via kids()) of every top-level section, body>div and body>main>div, skipping nav, footer, header, #cc-main and [data-w-id], fixed/sticky/absolute elements, and anything with top < innerHeight*0.92 at init. Playwright at 1440x900 found 40 marked elements (41 on a second run) on a 13,058 px document (13,132 and 13,471 on later runs; 12 sections, listed in /tmp/claude-0/-home-user-thatlayoverlife/16a08c1e-77ab-50a3-8cf3-b364d5e24f1b/scratchpad/p0/agents/p0-item1/out-base.txt).
- The hero does not wait: at scrollY 0 there were 0 marked elements in view (the r.top<vh*.92 guard excludes the above-the-fold hero). The first marked elements are the value section children at top 955 px (p.tll-val-ey, h2, p.tll-val-lede, div.tll-val-grid, div.tll-val-ask), all at computed opacity 0.01 and transform translateY(14px) at load.
- Measurement (live home, 1440x900, scroll 800 px every 400 ms, sampled every 100 ms; script /tmp/claude-0/-home-user-thatlayoverlife/16a08c1e-77ab-50a3-8cf3-b364d5e24f1b/scratchpad/p0/agents/p0-item1/measure-reveal.js, output out-base.txt): 13 of 17 landings had elements at opacity < 1 right after the scroll, min opacity 0.01 every time; the dim elements covered 9% to 74% of the viewport at landing (y=1600: 63%, y=6400: 73%, y=9600: 74%); time until every visible element reached opacity 1 was 720 to 1,043 ms (y=800: 1,031 ms, y=1600: 1,042 ms, y=4800: 1,043 ms, y=10400: 1,035 ms). At y=8800 one element never revealed within 1,500 ms.

It stays near invisible until the reader scrolls another 16 px or more.
- Other opacity rules checked and ruled out for the home page: the site head motion block (scratchpad/p1-pagecode-1107/after/site-head.html lines 323-355, style id tll-v91-motion-v1) defines '.tll-enter{opacity:0;transform:translateY(8px)}' with '--tll-t-enter:240ms' and a threshold .3 observer, but document.querySelectorAll('.tll-enter').length is 0 on the live home; the flow layer CSS (saved _home.html line 633, from src/site-layers/tll-flow-v1.css.html lines 11-15) has '.tll-flow-man .l{opacity:0;...transition:opacity .5s}' and '.tll-flow-reveal{opacity:0;transform:translateY(22px);transition:opacity .52s ...}' but 0 elements carry .tll-flow-reveal or [data-tll-reveal] on the live home; Webflow native interactions: 0 [data-w-id] elements and no inline opacity:0 styles in the saved or live home HTML. src/site-layers/tll-site-layers-v16.js contains no tll-rv, tll-enter or tll-flow-reveal rule.
- The site's own motion spec contradicts tllReveal 1.1.0: site-head.html line 324 reads 'one motion spec for the whole site. Enter: ease-out cubic-bezier(.23,1,.32,1), 200 to 300ms, opacity + 6 to 12px move' and line 327 sets '--tll-t-enter:240ms'. tllReveal uses 700 ms, 14 px and a different easing.
- Verification of the proposed values in Playwright (same protocol, /tmp/claude-0/-home-user-thatlayoverlife/16a08c1e-77ab-50a3-8cf3-b364d5e24f1b/scratchpad/p0/agents/p0-item1/measure2.js): (a) CSS-only override from the layers (override.css, out-css.txt): elements land at opacity 0.60 instead of 0.01 and reach 1 in 206 to 287 ms, but the y=8800 sliver still waits (now at 0.6, not 0.01) because the -40 px rootMargin is untouched. (b) tllReveal 1.2.0 (tllreveal-1.2.0.js, out-v2.txt, with rootMargin '0px 0px 20% 0px'): landing opacity 0.60, full in 208 to 344 ms with the 40 ms test stagger (the final file uses 30 ms steps capped at 2, so 300 ms worst case), max dim area at landing 52% instead of 74%, and the y=8800 stall is gone (344 ms). Fewer elements are ever dim because anything within 20% of the viewport below the fold reveals at once.
- Script order matters for a CSS override: the layers core loads synchronously in the head (live home line 692, tll-site-layers-v16.js from jsDelivr) and tllReveal appends its own <style id="tll-reveal-v1"> to head later from the footer, so a layers rule must win on specificity and !important, not order. 'html .tll-rv{...!important}' does, and '!important' also beats the inline style.transitionDelay that tllReveal sets per element.

Proposed change:

Two steps, smallest first.

Step 1 (site layers, no Webflow write besides the usual core re-register): add a parse-time style to the core. New file src/site-layers/tll-reveal-fast-v1.html containing exactly:
<style id="tll-reveal-fast-v1">
html .tll-rv{opacity:.6!important;transform:translateY(6px)!important;transition:opacity 240ms cubic-bezier(.23,1,.32,1),transform 240ms cubic-bezier(.23,1,.32,1)!important;transition-delay:0ms!important}html .tll-rv.tll-rv-in{opacity:1!important;transform:none!important}
</style>
and register it in STYLES in src/site-layers/build-site-layers-v16.py (the list at lines 29-37) as ('src/site-layers/tll-reveal-fast-v1.html', 'tll-reveal-fast-v1', 'section reveal: 240 ms from 0.6, 6 px, no stagger'), then rebuild and re-register the core per the release step at line 14. Measured result: landing opacity 0.60, fully visible in 206 to 287 ms, hero untouched. What it cannot fix: the -40 px rootMargin, so elements still start fading only once they are 40 px inside the viewport, and a sliver in the bottom 40 px sits at 0.6 until the next scroll.

Step 2 (complete fix, a registered-script update, not a Designer edit): register tllReveal 1.2.0 in the Webflow scripts registry and switch the site-wide footer entry from 1.1.0 to 1.2.0. Full source (1,818 bytes, syntax checked, tested in Playwright): /tmp/claude-0/-home-user-thatlayoverlife/16a08c1e-77ab-50a3-8cf3-b364d5e24f1b/scratchpad/p0/agents/p0-item1/tllreveal-1.2.0.js. It is 1.1.0 with four changes: style id tll-reveal-v2 and '.tll-rv{opacity:.6;transform:translateY(6px);transition:opacity .24s cubic-bezier(.23,1,.32,1),transform .24s cubic-bezier(.23,1,.32,1)}'; rootMargin '0px 0px 20% 0px' (elements start 20% of the viewport, 180 px at 900, before they enter); stagger dl=Math.min(i++,2)*30 (0, 30, 60 ms, so 300 ms worst case); cleanup at 300+dl ms. Everything else (SKIP list, kids(), the r.top<vh*.92 hero guard, the reduced-motion and tll-embed exits, print rule) is unchanged. Measured: 0.60 at landing, full in 208 to 344 ms with the 40 ms test stagger (300 ms with the final 30 ms), max dim area at landing 52% vs 74%, no stalled elements. Once 1.2.0 is live, the Step 1 style can stay (it is consistent with it) or be dropped.

Needs a Designer edit: no

Risks:

- Step 1 alone leaves the rootMargin dead band: an element whose only visible part is in the bottom 40 px stays at opacity 0.6 (seen at scrollY 8800, img.tll-rv at 876 to 1,380 px) until the reader scrolls on; only Step 2 removes that.
- Step 2 is a change to a Webflow registered script applied site-wide (all 14 saved pages load tllReveal), so it affects story pages, /the-map, /the-paw-passport and the legal pages too; it was measured on the home page only. The selection logic is unchanged, so the set of elements that animate is the same, only faster and lighter.
- With rootMargin +20%, elements between 828 and 1,080 px at load reveal immediately at DOMContentLoaded; on a slow first paint this could show a 240 ms fade on content the reader is already looking at. The r.top<vh*.92 guard still keeps the hero itself out.
- The layers override uses !important on transition, which also overrides tllReveal's inline transitionDelay; any future layer that wants a stagger on .tll-rv would need to live in the script, not CSS.
- Phone widths were not measured here (the review's own caveat); the reveal logic is not width dependent, but the 20% rootMargin is proportionally smaller on short viewports (about 130 px at 667 px high).
